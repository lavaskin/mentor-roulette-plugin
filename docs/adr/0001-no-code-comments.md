# 0001: No code comments; decisions live in ADRs

The code has no comments. Names, types and tests say what the code does, and a decision behind it (why it's this way when the obvious way would be wrong) is written in an ADR, grouped by topic, or on the `docs/` page for it. Comments drift from the code they describe, repeat what it already says, and excuse hacks that then get copied: an ADR is one place to read a topic's decisions, and a hack gets a ticket rather than an apology.

- **What takes a comment's place:** a clearer name, a test (one guarding against a bug that really happened says which in its name, ending `_Regression_<WhatWentWrong>`), an ADR or a `docs/` page for a decision, and a ticket for a hack that's still there. XML doc comments go too: nothing reads them, since `GenerateDocumentationFile` is off and the plugin isn't a library.
- **The workflows and scripts have none either.** Why they work the way they do is in [0008](0008-ci-and-releasing.md) and [releasing.md](../releasing.md).
- **Tool directives stay,** since tools read them: `// <auto-generated />`, `// ReSharper disable`, `// language=`, `# shellcheck` and shebangs. `#pragma`, `#nullable` and `#if` aren't comments.
- **CI holds the line** with its Check comments step, which runs `check-comments`, an action in [`lavaskin/ffxiv-workflows`](https://github.com/lavaskin/ffxiv-workflows#check-comments) that the API shares, so the two repos have one copy of the check. Its README has what it reads and how. It's a ratchet: the `baseline` in `.github/check-comments.json` lists how many comments each file may still have. It's empty, so any comment fails, naming the file and the line. A repo with comments left would list them there, and the check would fail on a file with more than its count, or with fewer until the baseline is lowered. It reads C# through Roslyn, so `//` inside a string isn't counted.
- **Running it locally,** with `ffxiv-workflows` cloned beside this repo: `dotnet run --file ../ffxiv-workflows/check-comments/check-comments.cs -- check` from the repo's root (`update` lowers the baseline, `list [path prefix]` prints every comment counted). It isn't part of `dotnet test`.
- **Removing comments,** after a merge brings some in, follows the repo's `delete-comment` agent skill (`.agents/skills/delete-comment/`).
